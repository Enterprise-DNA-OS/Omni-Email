# Omni Email — Master Implementation Plan

**38 features across 5 tiers, from foundation to fully autonomous inbox management.**

This plan was generated by running all 6 specialist agents against the full codebase. Every file path, migration, and API route has been validated against the existing code.

---

## How To Use This Plan

Each feature has:
- **Agent assignments** — which specialist agent owns each piece
- **Database migrations** — exact SQL
- **API routes** — endpoints to create
- **Components** — UI to build
- **Dependencies** — what must exist first

**Build order:** Tier 1 first (foundation), then Tier 2 (core autonomy), then 3/4/5 as needed. Within each tier, features are ordered by internal dependencies.

**Parallelization:** Features within the same tier can often be parallelized. The plan notes where Wave A/B/C parallel execution is possible.

CREATE TABLE public.audit_log (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  actor text NOT NULL CHECK (actor IN ('user', 'system', 'rule')),
  action text NOT NULL,
  target_type text NOT NULL,
  target_id uuid,
  details jsonb NOT NULL DEFAULT '{}',
  reversible boolean NOT NULL DEFAULT false,
  undone_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()

ALTER TABLE public.audit_log ENABLE ROW LEVEL SECURITY;
CREATE POLICY audit_log_select ON public.audit_log FOR SELECT TO authenticated
  USING (user_id = auth.uid());
GRANT ALL ON public.audit_log TO postgres, service_role;
GRANT SELECT ON public.audit_log TO authenticated;

## Sync Pipeline Extension

After Tier 2, the sync pipeline in `lib/email/sync.ts` runs this chain after each account sync:

```
1. classifyUnprocessedThreads()    — existing (intent + confidence + tags)
2. processAutoArchive()            — Tier 2 (archive high-confidence)
3. evaluateRulesForNewThreads()    — Tier 2 (user rules)
4. processAutoDrafts()             — Tier 2 (draft replies)
5. extractTasksForUser()           — Tier 2 (pull action items)
6. updateContactInteractions()     — Tier 3 (relationship tracking)
7. embedUnprocessedMessages()      — Tier 4 (semantic search)
8. extractEntities()               — Tier 5 (knowledge graph)
```

Each step is wrapped in try/catch and is non-fatal.

## Critical Architectural Decisions

1. **Single-pass AI classification** — Extend the classify prompt to return ALL fields at once (summary, category, priority, tags, intent, confidence, reasoning, signals, isNewsletter). One AI call per thread, not multiple.

2. **Background job consolidation** — Extend `app/api/internal/sync/route.ts` to call all processors in sequence after email sync. Only create separate Netlify functions for time-critical operations (daily summary, scheduled send at 1-min intervals).

3. **Semantic search as foundation** — pgvector embedding pipeline (Tier 4) is the foundation for chat-with-inbox, knowledge graph, and context-aware drafts. Prioritize embedding reliability.

4. **`user_preferences` table** — Design with extensible JSONB columns from the start to avoid constant migrations as new features add settings.

5. **Feature flags** — Consider a simple `user_preferences.feature_flags JSONB` column so Tier 4-5 features can be rolled out gradually.
